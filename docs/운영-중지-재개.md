# 개발 안 할 때 내리기·다시 올리기

기준일: 2026-10-29. dev 환경 비용을 줄이려고 **노드(EC2) 3대만 0으로 내리고**, 나머지(EKS·VPC·NAT·NLB·디스크·S3·Secret·DNS·인증서·Argo 설정)는 그대로 둔다. 내리기는 2026-10-29에 한 번 해 봤다(아래 실행 기록). 다시 올리기는 아직 해 보지 않았다.

## 1. 무엇이 남고 무엇이 꺼지나

| 구분 | 내렸을 때 | 비용(대략, 서울, 확인 안 한 단가) |
| --- | --- | --- |
| EC2 3대(app·platform·data)와 각 노드의 루트 디스크 | **꺼짐(종료)** | 0 |
| EKS 클러스터(제어부) | 남음 | 약 2.4달러/일 |
| NAT gateway | 남음 | 약 1.4달러/일 + 처리량 |
| NLB(Traefik) | 남음 | 약 0.5달러/일 |
| 공인 IPv4(NAT·NLB) | 남음 | 약 0.2달러/일 |
| PVC 디스크(EBS 92GiB: DB 30·Redis 5·Prometheus 30·Grafana 5·Alertmanager 2·Loki 10·Tempo 10) | **남음(데이터 그대로)** | 약 0.3달러/일 |
| S3(Loki·Tempo·state), Secrets Manager, Route53, ECR | 남음 | 하루 몇 센트 |
| **합계** | | **약 5달러/일(올려 둘 때 약 20달러/일)** |

- 내려 둔 동안 서비스(`https://nerdnam.click`)는 열리지 않는다. NLB는 남아 있지만 뒤에 받을 Pod가 없다.
- 로그·지표·trace 수집도 멈춘다. 내려 둔 기간은 Grafana에 빈 구간으로 남는다. 보존 기간(Prometheus·Loki 7일, Tempo 3일)은 계속 흐른다.
- **DB 데이터는 EBS 디스크에만 있다(S3 백업은 아직 없음).** 디스크는 Retain이라 노드가 꺼져도 지워지지 않는다. 그래도 `terraform destroy`나 PVC·StatefulSet 삭제는 하지 않는다.
- 더 줄이려면 NAT·NLB까지 지워야 한다. 그러면 다시 올릴 때 NLB 주소가 바뀌어 DNS도 고쳐야 해서 지금은 하지 않는다. 몇 주 이상 쓰지 않을 때는 따로 정한다(전체 철거는 데이터 백업이 생긴 뒤에).

## 2. 내리기 (약 5분, 3) 단계를 빼면 약 17분)

저장소 루트에서 실행한다. 기본 셸(zsh) 기준이다.

```sh
export AWS_PROFILE=nerdnam-infra
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN TF_DATA_DIR

# 0) 클러스터에 닿는지 확인. 안 되면 관리 IP가 바뀐 것이다 → 4절
kubectl --context nerdnam-dev get nodes

# 1) (BE를 쓰던 중이면) 진행 중 AI 작업이 없는지 확인. 있으면 끝날 때까지 기다리거나 drain 한다(앱-배포 문서 8절)
kubectl --context nerdnam-dev -n nerdnam exec deploy/api -- curl -s localhost:8081/actuator/aijob

# 2) data 노드를 먼저 비워 PostgreSQL·Redis를 정상 종료시킨다(디스크를 깨끗하게 닫음)
kubectl --context nerdnam-dev drain -l workload=data --ignore-daemonsets --delete-emptydir-data --timeout=5m
kubectl --context nerdnam-dev -n data get pods          # postgres-0·redis-0 가 Pending(자리 없음)이면 정상 종료된 것

# 3) 나머지 노드(app·platform)도 미리 비운다. 다 내리는 중이라 PDB 를 기다리지 않고 바로 지운다(--disable-eviction).
#    EKS add-on 의 PDB(coredns·ebs-csi-controller, 동시에 1개만)는 마지막 Pod 를 옮길 노드가 없어 막힌다. 이 단계를 빼면
#    AWS 가 노드마다 최대 15분 기다렸다 강제 종료한다(2026-10-29 첫 실행에서 17분 걸림).
#    data 노드에는 쓰지 않는다 — DB·Redis 는 2) 에서 PDB 없이도 정상 종료 절차를 거쳐야 한다.
kubectl --context nerdnam-dev drain -l 'workload in (app,platform)' --ignore-daemonsets --delete-emptydir-data --disable-eviction --timeout=2m

# 4) 노드 3대를 0으로. plan 에서 "aws_eks_node_group.this[...] will be updated in-place" 3개만 나오는지 본다
terraform plan  -var-file=eks.dev.tfvars -var eks_node_count=0 -out=stop.plan
terraform apply stop.plan
```

확인:

```sh
kubectl --context nerdnam-dev get nodes                 # No resources found
aws ec2 describe-instances --region ap-northeast-2 \
  --filters Name=tag:eks:cluster-name,Values=nerdnam-dev Name=instance-state-name,Values=running \
  --query 'length(Reservations[].Instances[])'          # 0
```

`stop.plan`은 다른 상태에서 다시 쓰지 않는다. 쓴 뒤 지운다.

## 3. 다시 올리기 (약 10~15분)

```sh
export AWS_PROFILE=nerdnam-infra
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN TF_DATA_DIR

# 0) 관리 IP 확인(바뀌었으면 4절 먼저)
curl -s -4 https://checkip.amazonaws.com

# 1) 노드 3대를 다시 1로. plan 에 노드 그룹 3개 변경만 있는지 본다
terraform plan  -var-file=eks.dev.tfvars -out=start.plan       # eks_node_count 기본값 1
terraform apply start.plan
```

노드가 뜨면 Pod는 Kubernetes가 알아서 다시 띄운다. Argo sync는 필요 없다(설정이 바뀐 게 아니다). 몇 분 기다린 뒤 확인한다.

```sh
kubectl --context nerdnam-dev get nodes -L workload                         # 3대 Ready
kubectl --context nerdnam-dev get pods -A | grep -v -E 'Running|Completed'  # 헤더만 남을 때까지 기다린다
kubectl --context nerdnam-dev -n data get pvc                               # data-postgres-0·data-redis-0 Bound(같은 디스크)
kubectl --context nerdnam-dev -n nerdnam exec deploy/api -- curl -s localhost:8081/actuator/health/readiness   # UP
curl -s -o /dev/null -w '%{http_code}\n' https://nerdnam.click/              # 200
kubectl --context nerdnam-dev -n argocd get applications                     # 모두 Synced·Healthy
```

- DB·Redis는 **같은 EBS 디스크가 새 data 노드에 다시 붙는다.** data 노드는 늘 같은 서브넷(2c)에 뜨므로 디스크와 AZ가 맞는다. 로그인 세션도 Redis AOF에 남아 있어 대부분 유지된다.
- NLB는 그대로이고, Traefik Pod가 새로 뜨면 LBC가 대상을 새 Pod IP로 바꾼다. 대상이 healthy가 되기까지 1~2분 걸릴 수 있다.
- 인증서는 Secret에 남아 있어 다시 발급하지 않는다. 오래 내려 둬서 만료 30일 전이 지났으면 cert-manager가 올라온 뒤 자동으로 갱신한다.

## 4. 관리 IP가 바뀌었을 때

EKS API는 `eks.dev.tfvars`의 `eks_public_access_cidrs`에 있는 IP만 받는다. `kubectl`이 `i/o timeout`으로 끊기면 IP가 바뀐 것이다.

```sh
curl -s -4 https://checkip.amazonaws.com                 # 새 IP
# eks.dev.tfvars 의 eks_public_access_cidrs 에 "<새 IP>/32" 를 넣는다(오래된 것은 뺀다)
terraform plan -var-file=eks.dev.tfvars -out=cidr.plan    # 내려 둔 상태면 -var eks_node_count=0 도 함께
terraform apply cidr.plan                                 # 1~2분
```

**주의: 내려 둔 상태에서 IP만 고칠 때는 `-var eks_node_count=0`을 꼭 같이 준다.** 빼먹으면 기본값 1로 노드 3대가 다시 켜진다.

IP가 끊긴 상태에서 bootstrap(Argo CD) apply를 하면, 실패하면서 Terraform state에서 Helm release가 빠질 수 있다(2026-10-29에 있었음, runbook 9절). bootstrap plan에 "to add"가 보이면 apply하지 말고 state부터 확인한다.

## 5. 하면 안 되는 것

- `terraform destroy`(루트·bootstrap): 클러스터·VPC가 지워진다. PVC 디스크는 남지만 새 클러스터에 붙이는 절차가 없고, 백업도 없다.
- Argo에서 `nerdnam-data` Application·PVC·StatefulSet 삭제
- 노드가 0인 동안 Argo sync를 시도하는 것(Argo도 꺼져 있다)
- `eks_node_count`를 2 이상으로(설계 밖, 검증 스크립트가 막는다)
