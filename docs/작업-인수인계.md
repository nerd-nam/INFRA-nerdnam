기준일: 2026-10-29. 구현 기준: 7단계 지표·로그 커밋(`feat: Prometheus·Grafana·Loki·Alloy 관측 구성`, 이 문서와 같은 커밋). 단계 세부는 [데이터-계층-작업계획.md](데이터-계층-작업계획.md)(5단계), [앱-배포-작업계획.md](앱-배포-작업계획.md)(6단계), [관측-작업계획.md](관측-작업계획.md)(7단계). 이 문서는 다음 세션이 대화 기록 없이 작업을 이어가기 위한 현재 상태 요약이다. AWS 실시간 상태를 이번 인수인계 작업에서 다시 조회하지 않았다.

## 1. 목표와 반드시 지킬 작업 범위

목표는 nerdnam의 FE·BE·AI·PostgreSQL·Redis와 운영/관측 도구를 Terraform과 Argo CD를 이용해 동일 EKS에서 운영하도록 배포 코드를 완성하는 것이다. 자체 GPU 모델 서빙은 폐기됐고 AI 서버가 Bedrock API를 호출한다.

사용자가 확정한 원칙:

- **지금은 코드 작성·검증만 진행한다.** 실제 인프라나 사용자의 apply 없이 다음 단계 코드를 계속 작성한다.
- **`terraform apply` / `terraform destroy`, AWS 리소스 변경, IAM 정책 연결, 실제 Kubernetes 배포를 임의로 실행하지 않는다.** 실제 실행은 별도의 명시적 요청이 있어야 한다.
- fmt/validate, mock provider Terraform 테스트, Helm lint/render 등으로 검증한다. 읽기 전용 조회와 실제 plan은 허용되지만 코드 작업의 필수 선행 조건은 아니다.
- 배포를 막으려고 `enable_eks` 같은 활성화 스위치를 만들지 않는다. 미확정 운영값은 필수 입력 변수와 예시 파일로 표현한다.
- **각 구현 단계는 검증 후 커밋한다. push는 별도 요청 시에만 수행한다.**
- **PostgreSQL 일일 S3 백업과 새 PVC 복원 시험은 보류한다.** 백업 bucket·CronJob·IAM·snapshot도 현재 구현 범위에 넣지 않는다.
- HPA·Karpenter·Cluster Autoscaler는 계획에 없다. 정상 운영 워커는 역할별 1대, 총 3대다.
- 코드 검증과 배포 후 검증을 구분한다. 노드 Ready·HTTPS·Secret 주입·PVC 데이터 유지가 확인됐다고 쓰지 않는다.

저장소의 `AGENTS.md`에 이 작업 원칙이 기록돼 있다. 옛 GPU 구성 문서나 과거 대화보다 현재 코드와 최신 구축 계획을 우선한다.

## 3. 합의된 구성

EKS control plane은 AWS 관리형이다. 아래 EC2 3대는 모두 같은 EKS의 워커이며, 데이터 EC2가 클러스터 밖에 있는 구성이 아니다.

| 노드 그룹 | 초기 인스턴스 후보 | 위치 | 담당 |
| --- | --- | --- | --- |
| app | `m7i.xlarge`, 4 vCPU / 16 GiB | public-a | FE·BE·AI·Traefik |
| platform | `m7i.xlarge`, 4 vCPU / 16 GiB | private-c | Argo CD·controller·Prometheus/Grafana/Loki/Tempo 등 |
| data | `m7i.large`, 2 vCPU / 8 GiB | private-c | PostgreSQL+pgvector·Redis |

- 각 MNG는 min/desired/max=1. MNG 교체 시 일시 추가 EC2가 생길 수 있다.
- `workload=app|platform|data` 라벨, platform/data에 해당 `dedicated=...:NoSchedule` taint. Pod에는 선택자와 toleration을 함께 둔다.
- CPU x86_64 / AL2023. GPU 노드 없음. 용량은 실측 전 후보다.
- AWS 계정 `082139775699`, 리전 `ap-northeast-2`. AWS 조회용 기존 profile은 `nerdnam-infra`.
- VPC `10.20.0.0/16`, public `10.20.0.0/24`(2a)와 private `10.20.16.0/20`(2c) 각 하나. EKS에는 서로 다른 두 AZ의 subnet을 등록한다.
- IGW, public NAT 1개, route table, 두 route table에 S3 gateway endpoint.
- EKS API는 private 활성화 + public 관리자 CIDR 제한.
- 인터넷 → NLB TCP 80/443 → Traefik → FE/BE. TLS는 Traefik에서 종료하고 cert-manager가 Route53 DNS01으로 인증서를 발급한다.
- Argo CD·Grafana는 초기 관리자 port-forward 접근. DB·Redis·AI는 공개하지 않는다.
- 역할별 1대이므로 HA/무중단 구성이 아니다. private-c 장애는 data/platform 양쪽에 영향을 준다.

AWS root state는 기존 S3 bucket `nerdnam-terraform-082139775699-ap-northeast-2-an`의 `dev/terraform.tfstate`, bootstrap state는 같은 bucket의 `dev/bootstrap.tfstate`를 사용한다. state 경로를 임의 변경하지 않는다. bootstrap은 AWS state outputs에서 endpoint/CA와 필요한 식별자를 읽는다.

AWS Terraform은 AWS 리소스와 EKS add-on, bootstrap은 Argo CD 설치, Argo는 나머지 Kubernetes 리소스를 소유한다. LBC가 만드는 NLB와 EBS CSI가 만드는 PV용 EBS를 Terraform에서 중복 선언하지 않는다.

현재 EKS add-on은 VPC CNI·CoreDNS·kube-proxy·Pod Identity Agent·EBS CSI다. CNI/CSI는 전용 Pod Identity 역할을 사용하며 CNI NetworkPolicy 활성화 설정이 있다. 미지정 add-on 버전은 plan 때 AWS 기본 호환 버전을 조회한다. 실제 버전/schema 고정은 배포 준비 시 검증해야 한다.

## 6. 4단계에서 이어받을 주의점

- Argo Application은 초기 **수동 sync**, 자동 prune/finalizer 없음. controller CRD/webhook Ready를 확인한 뒤 CR Application을 동기화하도록 설계했다.
- AWS Secrets Manager에는 `nerdnam/dev/backend`, `nerdnam/dev/data`, `nerdnam/dev/ai` 메타데이터만 있다(코드 선언 기준). 실제 값/SecretVersion을 Terraform에 넣지 않는다.
- ESO는 controller Pod Identity와 ambient auth를 사용한다. store 사용 namespace는 nerdnam/data, IAM read 권한은 3개 Secret으로 제한한다. 공유 store이므로 namespace 사이 완전한 Secret 격리는 아니다.
- `nerdnam`/`data`에 기본 ingress/egress 차단과 DNS 허용, 5단계의 BE(`app: api`) → PostgreSQL/Redis 양방향 정책이 있다. 6단계에서 Traefik→web/api, web→api, api→ai, api/ai→외부 443, ai→Pod Identity Agent를 추가했다. 7단계에서 Prometheus→api 관리 포트·exporter, 8단계에서 web/api/ai→monitoring/alloy:4318을 추가했다.
- `gp3-retain`: encrypted, WaitForFirstConsumer, Retain, 확장 허용. namespace/StorageClass/데이터 StatefulSet에는 Argo 삭제 보호가 있다. 업무 PVC는 StatefulSet `volumeClaimTemplates`(postgres 30Gi, redis 5Gi)로만 선언한다.
- DNS01 TXT와 실제 웹 도메인의 NLB A alias/CNAME은 별개다. 웹 DNS 레코드 자동 생성은 아직 없다.
- private Git 최초 repository credential은 ESO보다 먼저 필요하므로 별도 공급 대상이다. Git/Terraform state에 자격 증명을 넣지 않는다.
- IAM 정책은 실효 권한 검증 전 초안이다. platform 실행자 정책의 inline policy/trust 편집 권한은 강하므로 최소 권한이 완전히 검증됐다고 표현하지 않는다.
- 로컬 커밋만 수행했다. Argo가 읽을 revision은 추후 원격 Git에도 존재해야 한다. 임의 push하지 않는다.

- 로컬 Docker로 렌더된 PostgreSQL/Redis 설정과 BE `24c38d8` 연동(데이터 계층 문서 9절), web/api/ai의 Pod 보안 조건 실행과 web→api 경로(앱-배포 문서 9절), exporter(관측 문서 7절), Alloy→Tempo→S3 호환 저장소(추적 문서 7절) 확인. 클러스터 검증이 아니다.
- NLB/TLS·Secret 참조·보존·필수 입력 누락 검사, IAM JSON 및 정책 크기 검사 통과.
- 실제 plan은 이전에 `eks:DescribeAddonVersions` AccessDenied로 완료되지 않았다. 과거 조회가 지연된 39개 plan을 현재 호환성 검증 결과로 재사용하지 않는다.

루트와 `bootstrap/`에서 각각 별도 임시 TF_DATA_DIR로 검증한다. 아래는 실제 AWS apply가 아니다.

```sh
export TF_DATA_DIR="$(mktemp -d)"
terraform init -backend=false -input=false -lockfile=readonly
terraform validate
terraform test
unset TF_DATA_DIR
```

저장소 루트에서:

```sh
terraform fmt -check -recursive
git diff --check
python3 scripts/validate_gitops.py --helm /path/to/helm --cache /tmp/nerdnam-chart-cache --fetch
```

Python 의존성은 `scripts/requirements-validation.txt`를 사용한다. Helm 검증은 공식 chart·Kubernetes OpenAPI 다운로드(`--fetch`, SHA256 확인)와 로컬 렌더링만 하며 클러스터에 접속하지 않는다. cache가 있으면 `--fetch`를 생략한다. 이전 세션의 임시 Helm/라이브러리/cache는 `/private/tmp/nerdnam-gitops-tools`에 있었으나 다음 세션에서도 존재한다고 가정하지 않는다. 검증 시 Helm 3.19.0, Terraform 1.16.1을 사용했다. provider 버전은 각 `.terraform.lock.hcl`을 따른다.

실제 webhook·AWS SDK/IAM·DNS·인증서 발급·Secret 동기화·노드 Ready·PVC 보존은 아직 검증하지 않았다. 실제 값이나 권한이 없어도 5단계 코드 작성은 계속한다.
