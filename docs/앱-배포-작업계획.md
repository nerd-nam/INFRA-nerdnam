# 6단계 앱 배포 (FE·BE·AI)

기준일: 2026-10-28. 상태: **INFRA 쪽 코드·로컬 검증 완료, 미배포.** 이 문서의 "확인함"은 로컬 Helm 렌더링·Terraform mock 테스트·로컬 Docker 실행 결과다. EKS 위 실행, Pod Identity 자격 증명, 실제 Bedrock 호출, OAuth 로그인, NetworkPolicy 차단은 배포 후 검증할 항목이다.

기준 앱 커밋: FE `42e2946`, BE `24c38d8`, AI `origin/main` `df3e23e`(로컬 checkout은 4커밋 뒤라 pull 하지 않고 원격 기준으로 읽음). SPEC v1.64.

범위 밖: 앱 저장소 코드·workflow 변경(아래 7절에 할 일로 정리), 관측(7·8단계), S3 백업.

## 1. 구성

| | web (FE) | api (BE) | ai (AI) |
| --- | --- | --- | --- |
| 이미지 | ECR `nerdnam-dev/web` digest | ECR `nerdnam-dev/api` digest | ECR `nerdnam-dev/ai` digest |
| 포트 / Service | 3000 / `web` | 8080 / `api` | 8000 / `ai` |
| 실행 사용자 | uid 100 / gid 101 (이미지의 `web`) | 10001 (이미지의 `nerdnam`) | 65532 (이미지에 USER 없음 → 비root 지정) |
| 자원 | 100m / 256Mi, limit 512Mi | 500m / 1.5Gi, limit 2Gi (`MaxRAMPercentage=75`) | 250m / 512Mi, limit 1Gi |
| 교체 | RollingUpdate (surge 1) | **Recreate** | RollingUpdate (surge 1) |
| 종료 유예 | 30초 + preStop 5초 | 90초 | 330초 + preStop 5초 |
| readiness | `GET /favicon.ico` | `GET /actuator/health` (DB·Redis 포함) | `GET /health` |
| liveness | TCP 3000 | TCP 8080 (startup TCP 최대 5분, Flyway) | `GET /health` |

- 모두 app 노드(`workload=app`), replica 1, 읽기 전용 root, capability 제거, ServiceAccount token 자동 마운트 없음. 쓰기 경로는 emptyDir(`/tmp`, FE `/app/.next/cache`).
- **BE probe**: BE 보안 설정이 `/actuator/health`만 열어 두어 `/actuator/health/liveness`·`readiness`는 401이다(로컬에서 확인). 그래서 liveness는 포트만 보고, DB·Redis 장애는 readiness에만 반영해 무한 재시작을 피한다.
- **BE Recreate**: 앱 시작 Flyway와 메모리 작업 큐 때문에 두 버전이 동시에 뜨지 않게 한다. 교체 중에는 API가 중단된다.
- **AI /health**: 모델이 loading·error여도 200이다. 프로세스 확인용으로만 쓰고, 모델 미준비 요청은 AI가 503 → BE가 `GPU_UNAVAILABLE`로 처리한다.

## 2. 공개 경로와 HTTPS

```text
인터넷 → NLB(TCP 443) → Traefik(TLS 종료, 인증서 nerdnam-web-tls)
  /api, /oauth2, /login/oauth2  → api:8080
  그 밖 전부                     → web:3000  (web 은 SSR·rewrites 로 api 를 다시 부른다)
```

- 80 → 443 리다이렉트는 Traefik 설정(4단계)에 있다. `/actuator`·AI는 공개 경로에 없다(web 쪽 404 확인).
- 인증서: `Certificate nerdnam-web`(DNS01, `nerdnam-acme`). 도메인은 bootstrap 입력 `app_hostname` → `environment.appHostname`.
- BE는 `SERVER_FORWARD_HEADERS_STRATEGY=native`로 Traefik의 `X-Forwarded-*`를 믿는다(Tomcat 기본 내부 프록시 대역 10.x 포함). 로컬에서 OAuth 시작 응답의 `redirect_uri`가 `https://<도메인>/login/oauth2/code/google`, 세션 쿠키가 `Secure; HttpOnly; SameSite=Lax`인 것을 확인했다.
- **OAuth 콘솔 등록**: Google·Kakao에 `https://<app_hostname>/login/oauth2/code/google`, `…/kakao`를 redirect URI로 등록한다.
- 웹 도메인의 DNS 레코드(NLB 주소를 가리키는 A alias/CNAME)는 아직 자동 생성하지 않는다. 배포 후 수동으로 만든다(4단계와 같음).

## 3. 설정과 비밀값

BE 환경 변수는 [데이터 계층 문서](데이터-계층-작업계획.md) 5절과 같고, 추가로:

| 환경 변수 | 값 |
| --- | --- |
| `NERDNAM_AUTH_MODE` | `session` |
| `NERDNAM_AUTH_WEB_ORIGIN` | `https://<app_hostname>` |
| `NERDNAM_AUTH_LOGIN_SUCCESS_URL` / `_FAILURE_URL` | `https://<app_hostname>/`, `…/?login=failed` |
| `NERDNAM_AI_STUB` / `NERDNAM_AI_BASE_URL` | `false` / `http://ai.nerdnam.svc.cluster.local:8000` |
| `SERVER_FORWARD_HEADERS_STRATEGY`, `SERVER_SERVLET_SESSION_COOKIE_SECURE` | `native`, `true` |

- 비밀값은 `envFrom: backend-secrets` 하나로 받는다. Secrets Manager `nerdnam/dev/backend` JSON 키: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`. DB·Redis 비밀번호 3개는 `nerdnam/dev/data`에서 ESO가 넣는다(5단계). backend JSON에 그 세 키를 넣지 않는다.
- FE: `API_ORIGIN=http://api.nerdnam.svc.cluster.local:8080`. **이미지 빌드 때도 같은 값이어야 한다**(next.config rewrites가 빌드 때 정해짐). 실행 env는 SSR 코드용이다.
- AI: `AI_MODE=real`, `AWS_REGION`, `LLM_MODEL=global.amazon.nova-2-lite-v1:0`, `EMBED_MODEL_ID=amazon.titan-embed-text-v2:0`, `AWS_EC2_METADATA_DISABLED=true`(노드 역할로 넘어가지 않게). `AWS_BEARER_TOKEN_BEDROCK`·정적 키는 넣지 않는다. `nerdnam/dev/ai` Secret은 지금 쓰지 않는다(Pod에 연결하지 않음).

## 4. AI의 Bedrock 권한 (Terraform `modules/workload`)

- 역할 `nerdnam-dev-ai`, EKS Pod Identity로 `nerdnam/ai` ServiceAccount에만 연결. trust는 클러스터 ARN·namespace·SA 태그 조건.
- 권한은 `bedrock:InvokeModel` 하나(Converse도 이 권한). AI 코드가 `converse`·`invoke_model`만 쓰는 것을 확인했다.
  - Titan 임베딩: `arn:aws:bedrock:ap-northeast-2::foundation-model/amazon.titan-embed-text-v2:0`, 요청 리전 서울.
  - Nova 2 Lite Global 프로필: AWS 문서의 3단 구성 — 서울 inference-profile, 서울 foundation-model(`bedrock:InferenceProfileArn` 조건), 리전 없는 global foundation-model(`aws:RequestedRegion=unspecified` + 프로필 조건).
- boto3/botocore 1.43.119는 Pod Identity 자격 증명을 지원한다. AI Pod egress는 Pod Identity Agent `169.254.170.23:80`과 외부 443만 연다.
- 조직 SCP가 리전을 막고 있다면 `unspecified` 허용이 필요하다(문서 기준, 이 계정의 SCP는 확인하지 않음).

## 5. 이미지 CI와 배포 흐름

```text
앱 저장소 main merge → 테스트 → 이미지 빌드 → GitHub OIDC 로 nerdnam-dev-ci-<web|api|ai> 역할 → ECR push
  → INFRA 의 gitops/apps/images.yaml digest 를 바꾸는 PR → merge → Argo 수동 sync → 확인
```

- Terraform `modules/workload`가 GitHub OIDC provider와 CI 역할 3개를 만든다. 각 역할은 **해당 저장소의 `main` 브랜치 workflow만** 받을 수 있고(`sub = repo:nerd-nam/<repo>:ref:refs/heads/main`), **자기 ECR repository에만** push한다. 저장소 이름·브랜치는 변수(`github_repositories`, `ci_branch`)다.
- 계정에 같은 URL(`token.actions.githubusercontent.com`)의 OIDC provider가 이미 있으면 생성이 실패한다. 그때는 `terraform import module.workload.aws_iam_openid_connect_provider.github <ARN>`으로 가져온다. 현재 실행 사용자에게 `iam:ListOpenIDConnectProviders` 권한이 없어 존재 여부를 확인하지 못했다.
- 이미지 digest는 Terraform·bootstrap이 아니라 Git의 `gitops/apps/images.yaml`이 소유한다(root Application이 `valueFiles: [images.yaml]`로 읽음). 지금은 비어 있어 렌더링이 실패한다 — 첫 이미지 push 전에는 `nerdnam-apps`를 sync하지 않는다. 가짜 digest를 넣지 않는다.
- INFRA PR을 자동으로 만드는 GitHub App/토큰은 아직 없다. 처음에는 사람이 digest를 옮겨 PR을 만든다.
- ECR은 IMMUTABLE 태그다. 태그는 commit SHA를 권장한다. 배포 정의는 태그가 아니라 digest로 고정한다.

앱 저장소 workflow 예시(각 저장소에 추가할 것, 아직 추가하지 않음):

```yaml
permissions: {id-token: write, contents: read}
jobs:
  image:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with: {role-to-assume: "<terraform output workload.ci_role_arns.api>", aws-region: ap-northeast-2}
      - id: ecr
        uses: aws-actions/amazon-ecr-login@v2
      - run: |
          ref=${{ steps.ecr.outputs.registry }}/nerdnam-dev/api:${GITHUB_SHA}
          docker build -t "$ref" .            # FE 는 --build-arg API_ORIGIN=http://api.nerdnam.svc.cluster.local:8080
          docker push "$ref"
          docker inspect --format '{{index .RepoDigests 0}}' "$ref"   # images.yaml 에 넣을 값
```

## 6. 통신 정책 (nerdnam namespace)

foundation의 default-deny와 DNS 허용, 5단계 `allow-api-to-data` 위에:

| 출발 → 도착 | 포트 |
| --- | --- |
| traefik namespace → web | 3000 |
| traefik namespace, web → api | 8080 |
| api → ai | 8000 |
| api → 외부(사설 대역 제외 0.0.0.0/0) | 443 (Google·Kakao OAuth) |
| ai → 외부(사설 대역 제외) | 443 (Bedrock) |
| ai → Pod Identity Agent `169.254.170.23/32` | 80 |

- web은 api 말고는 나갈 곳이 없다. web·ai는 DB·Redis에 닿지 않는다. IMDS(169.254.169.254)는 모두 막힌다.
- 외부 443을 도메인 단위로 좁히지는 못한다(NetworkPolicy는 IP 기준). 더 좁히려면 egress proxy가 필요하다.
- 7단계에서 Prometheus 수집·OTLP 전송 경로를 추가한다.
- nerdnam namespace에 ResourceQuota(LoadBalancer·NodePort·PVC 0개, rolling update 여유 포함)와 LimitRange를 둔다.

## 7. 앱 저장소에 필요한 변경 (INFRA 밖, 아직 하지 않음)

| 저장소 | 변경 | 이유 |
| --- | --- | --- |
| FE | `public/` 폴더 추가(빈 `.gitkeep`이라도) | **현재 Dockerfile이 `COPY /app/public`에서 실패한다.** 로컬 검증은 임시 복사본에 빈 폴더를 넣어 빌드했다 |
| 전체 | 5절 workflow 추가 | ECR push |
| BE | `/actuator/health/**` 허용(liveness·readiness 그룹) | probe를 프로세스·준비 상태로 나누기. 그 뒤 INFRA probe 경로를 바꾼다 |
| BE | Prometheus registry·관리 포트 | 7단계 |
| BE | 신규 AI 작업 접수 중지·배출 확인 | 배포 때 진행 중 작업 보호. 지금은 점검 창 배포로 대신한다 |
| AI | Dockerfile에 비root `USER` | 지금은 Kubernetes가 uid 65532로 강제 실행(로컬에서 동작 확인) |
| AI | `/readyz`(모델 상태 반영, 유료 호출 없이) | readiness가 모델 준비를 반영하게 |
| AI | 전역 동시 호출 상한 | Bedrock 한도 (구축 계획 7장) |

## 8. 배포 순서와 운영 (사용자가 실행)

1. AWS 루트 apply(`modules/workload` 포함) → bootstrap apply(`app_hostname` 입력).
2. Secrets Manager `nerdnam/dev/backend`에 OAuth 키 4개, `nerdnam/dev/data`에 5단계 키 4개 공급.
3. 앱 저장소에서 이미지 push → `images.yaml` digest PR merge.
4. 수동 sync: foundation → secrets → data(Ready 확인) → apps. BE 첫 기동 때 Flyway가 V1~V8을 적용한다.
5. NLB 주소로 웹 도메인 DNS 레코드 생성 → 인증서 발급 확인 → OAuth 콘솔 redirect URI 등록 → 로그인 확인.

- BE 배포(Recreate)는 진행 중 AI 작업을 끊는다. 점검 창에서 한다.
- rollback은 `images.yaml`의 이전 digest로 되돌리는 PR이다. DB schema는 되돌아가지 않는다(V6 이전 768차원 앱으로 복귀 불가).
- 자동 sync는 켜지 않았다. FE부터 켜는 것은 배포 후 검증 뒤에 결정한다.

## 9. 검증 결과

로컬 검증(2026-10-28):

- `scripts/validate_gitops.py`: 자체 chart 7개, CR 18개 CRD schema, **기본 객체 42개를 Kubernetes 1.35 공식 OpenAPI로 엄격 검사**(모르는 필드·형식 오류 거부, schema 파일 SHA256 고정). apps 검사: ECR digest 이미지, 배치·보안, BE probe 경로, Recreate, 환경 변수 계약, 공개 경로, 통신 정책을 Pod 쌍으로 계산해 기대값과 비교, quota가 rolling update를 막지 않는지. `images.yaml`이 비었거나 ECR digest가 아니면 실패. 필드 오타·잘못된 probe 경로·BE RollingUpdate·형식 오류·web→ai 허용을 일부러 넣어 실패하는 것도 확인했다.
- Terraform: AWS 루트 mock 테스트 13개(workload 3개 추가: Bedrock 리소스 4개와 조건, CI trust의 저장소·브랜치, push 범위, global이 아닌 프로필 거부), bootstrap 1개(app_hostname 전달, 이미지는 bootstrap에 없음) 통과.
- 로컬 Docker(Pod와 같은 uid, 읽기 전용 root, capability 제거, 클러스터 DNS 이름을 network alias로):
  - web: `/`·`/library` 200, `/api/auth/csrf`가 `api.nerdnam.svc.cluster.local:8080`으로 전달되어 CSRF 토큰 응답, `/actuator/health` 404.
  - api: prod 프로필로 기동, 위 OAuth `redirect_uri`·Secure 쿠키 확인, `/actuator/health` 200 / `health/liveness`·`readiness`·`prometheus`·`env` 401.
  - ai: uid 65532·읽기 전용으로 기동, 자격 증명이 없으면 `NoCredentialsError`로 모델 `error` 상태(정상: EKS에서는 Pod Identity), `/health` 200.

배포 후 검증할 것: Pod Identity로 실제 Bedrock 호출, ESO→BE 비밀값, 인증서 발급·HTTPS, OAuth 로그인 왕복, NetworkPolicy 실제 차단(AI→DB, web→AI 등), BE 교체 중 동작, 메모리 사용량.
